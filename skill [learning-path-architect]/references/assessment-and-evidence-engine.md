# Assessment and Evidence Engine

Use this reference for diagnostics, readiness, mastery checks, remediation, transfer, and unlocking decisions.

## Assessment selection

Choose the smallest assessment that can change the route: diagnostic questions for awareness/concepts; worked problems for reasoning; coding or debugging tasks for implementation; design reviews for architecture; failure injection for resilience; source/provenance audits for research/OSINT; replication for scientific work; teach-back for explanation; transfer tasks for unfamiliar contexts; and capstones for integration.

Every assessment record states the capability, context, constraints, inputs, expected observable behavior, rubric, pass standard, assistance allowed, safety boundary, evidence artifact, common failure class, remediation, and recheck trigger.

## Interpretation

Separate exposure, guided completion, practice, independence, transfer, retention, maintenance, stale evidence, contradiction, and unknown. Use multiple observations across familiar and novel tasks when the claim is important. A package validator, tutorial, one local demo, or self-report proves only what its context supports.

## Failure-to-intervention

Classify the smallest likely gap before prescribing more content: concept, prerequisite, procedure, debugging, environment, interface contract, data quality, transfer, retention, capacity, or safety/authorization. Assign a targeted intervention and expected improvement signal. If a milestone fails, recheck after remediation instead of expanding the syllabus automatically.
