# Clarification Triage

Use only when the request is too unconstrained to define a useful destination or when competing interpretations would produce radically different maps. Do not ask these questions for a reasonably interpretable request.

Ask up to three questions, preferably in one concise message:

1. **Deliverable or end context:** What specific project, decision, or real-world capability should the learner be able to demonstrate at the end?
2. **Baseline audit:** What have they already built, analyzed, operated, or debugged in this or adjacent domains?
3. **Operational constraints:** What environment, toolchain, access, safety boundaries, and time or effort budget are relevant?

If the user cannot answer, proceed with conservative assumptions, state them, and provide a short diagnostic or multiple plausible routes instead of blocking indefinitely.
