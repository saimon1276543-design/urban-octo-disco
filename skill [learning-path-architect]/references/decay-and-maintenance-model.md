# Capability decay and maintenance model

Use this reference for long horizons, pauses, retention-sensitive goals, and capability-state recalibration.

## Decay classes

Classify each capability by dominant decay behavior: factual recall, mathematical fluency, procedural skill, programming fluency, volatile tool knowledge, clinical or safety-sensitive knowledge, or project-maintenance ability. The class is a planning heuristic, not a universal biological law.

## Maintenance fields

For each retained or completed capability record expected decay sensitivity, last successful retrieval or performance, minimum maintenance evidence, suggested review interval, reactivation cost, consequence if stale, and whether supervision or current verification is required. Use observed learner data when available; otherwise mark the interval as inferred or unknown.

## Decisions

Use maintained when the capability is still evidenced in its target context. Use stale when the relevant interval has passed without adequate evidence or when a volatile dependency changed. Use contradicted when later evidence conflicts with the prior state. Maintenance may be a small retrieval, transfer sample, artifact review, or supervised recheck; it is not automatically a second full course.

When capacity is constrained, protect high-leverage, safety-sensitive, frequently used, and expensive-to-reactivate capabilities first. Explain what is being maintained, deferred, or allowed to decay and the cost of reactivation.
