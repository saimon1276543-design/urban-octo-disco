# Learning-plan quality check

Use this checklist before delivering a roadmap, syllabus, portfolio, or revision. Keep the check internal unless the learner asks for an audit.

## User usefulness

- State the learner’s requested outcome in plain language.
- Identify one primary next action.
- Keep the immediate answer small enough to use today.
- Explain why the first action comes first.
- Name the expected result or artifact.
- State what counts as enough evidence to continue.
- State what to do if the learner gets stuck.
- State the next review trigger.

## Coverage and route

- Preserve every meaningful explicit goal.
- Mark each goal as active, planned, deferred, optional, alternative, conflictual, or context.
- Distinguish required prerequisites from helpful enrichment.
- Avoid false linearity when branches can be parallel or iterative.
- Keep sibling nodes at similar levels of detail.
- Avoid adding a topic unless it closes a justified gap or changes a decision.
- Preserve stable identifiers when revising an existing plan.

## Evidence and adaptation

- Do not treat exposure or reading as independent mastery.
- Match evidence to the intended context and proficiency level.
- Record unknown when evidence was not checked.
- If the learner is stuck, diagnose the smallest likely gap before adding content.
- Use a bounded correction with an observable improvement signal.
- Include maintenance or revalidation when the capability can decay or the knowledge can change.
- Use a representative pilot when current level, effort, or route fit is uncertain.
- Preserve the original assumption and the reason for every material route change.
- After a missed task, preserve completed work and choose resume, reduce, split, reschedule, or deliberate pause rather than automatic backfilling.

## Honesty and safety

- Label assumptions and current-information dependencies.
- Distinguish researched facts from pedagogical recommendations.
- Do not claim persistence, synchronization, database access, scheduling, or MCP access without verification.
- Do not imply professional authorization, licensure, clinical competence, or regulated permission.
- State limitations when a requested format, tool, or integration is not supported.

## Complexity control

- Load only the references needed for the request.
- Keep the full architecture available without displaying it all at once.
- Expose a current action, not an unprioritized table of contents.
- Offer deeper details as optional follow-up rather than forcing them into the first answer.
