# Freshness, Deprecation, and Compatibility Control

Use this reference when a route depends on current tools, APIs, protocols, curricula, models, browsers, or regulations.

## Claim record

Track claim ID, stable capability IDs affected, source, source date, version/region, confidence, volatility class, compatibility status, deprecation state, conflicts, impact, and next revalidation trigger. Keep durable principles separate from current implementation claims.

## Revalidation

Use targeted refresh for one tool or claim, domain refresh for a branch, drift scan for a changing portfolio, and full review only when many interfaces changed. Queue version changes, deprecations, source conflicts, safety changes, evidence shifts, context changes, integration failures, and learner requests.

## Compatibility matrix

For browser tools, CDP, MCP, LangChain/LangGraph/LlamaIndex, model/GPU stacks, medical curricula, and exam policies, record environment, component versions, supported capability, status, source, known limitations, and trigger. Never infer current support from a past successful run or a product name alone.

## Update report

State what changed, what stayed stable, what was not checked, affected capabilities, evidence consequences, uncertainty, and the next review. Do not silently rewrite durable foundations when only an API or policy changed.
