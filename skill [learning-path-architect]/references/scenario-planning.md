# Scenario Planning and What-If Analysis

Use this reference when the learner is choosing between routes or asks what happens if capacity, priorities, domains, deadlines, access, tools, or context change.

## Scenario inputs

Vary only decision-relevant variables: north star, target depth, reliable capacity, concurrency limit, horizon/deadline, required/optional families, access/cost, online/offline availability, safety boundary, volatility, and breadth-versus-depth preference.

## Comparison dimensions

Compare scenarios by time to first useful capability, target evidence, prerequisite leverage, domain coverage, bridge leverage, switching load, maintenance, uncertainty, reversibility, cost/access, safety constraints, and route fragility. Use qualitative bands or learner-supplied weights; never present invented precision.

## What-if sequence

1. Copy the current graph as a proposed scenario.
2. Apply one material change.
3. Recompute affected dependencies, critical path, active frontier, capacity load, evidence, maintenance, freshness, and risk propagation.
4. Identify newly blocked, unlocked, overloaded, stale, deferred, or unresolved nodes.
5. Compare the smallest viable alternatives.
6. Preserve the current authoritative route until the learner chooses or the approved revision protocol commits a change.

Retain rejected or deferred scenarios with reasons, assumptions, reversal conditions, and review triggers. Adding a fifth large domain is not free; reducing capacity should produce explicit deferred scope rather than unrealistic compression.
