# Freshness Protocol

Use this reference whenever a learning path contains technologies, APIs, frameworks, cloud services, regulations, standards, security practices, research claims, labor-market expectations, or other content that may have changed. The bundled domain modules are orientation scaffolds, not authoritative current curricula.

## Default rule

Use **strict freshness mode** by default. For every new use of the skill that names a concrete domain, technology, framework, platform, standard, regulation, security practice, research area, or industry role, perform current web research before finalizing the map. Do not rely on bundled domain references alone, even when their conceptual content appears stable; domain structure, accepted tooling, evidence expectations, and boundaries can change.

Only use the **timeless exception** when the request is explicitly abstract and contains no current domain, tool, ecosystem, regulatory, or practice claim—for example, a purely conceptual explanation of recursion. If the user requests a domain syllabus, roadmap, current competency, tool choice, or practical outcome, research is required. If research cannot be completed, state that limitation and keep current claims out of the output rather than silently using stale references.

## Research sequence

1. Identify the claims that require freshness rather than researching the entire domain indiscriminately.
2. Search broadly enough to discover the current official sources, then open and read the relevant source pages rather than relying on snippets.
3. Prefer primary sources: official documentation, standards bodies, RFCs, vendor manuals, government or regulator publications, original papers, and maintained project documentation.
4. Cross-check consequential claims with a second authoritative or independent source when practical, especially for security, safety, regulations, breaking changes, or disputed practice.
5. Record the source title, URL, publisher, access date, applicable version or date range, and the exact claim or node it supports.
6. Mark unresolved uncertainty, regional variation, version assumptions, and likely expiry conditions. If current verification is unavailable, say so and avoid presenting the claim as settled fact.

## What to update

Use current research to update tool names, version-specific prerequisites, recommended workflows, deprecated practices, ecosystem alternatives, security boundaries, standards, regulations, and evidence expectations. Do not rewrite stable conceptual foundations merely because a new tool version exists.

## Output behavior

For strict freshness mode, include a concise **Freshness and sources** section in every domain-grounded output, even when research confirms that the existing structure remains suitable. State the research cutoff, context, main authoritative sources, affected or confirmed nodes, uncertainty, and recheck trigger. Cite sources next to relevant claims or nodes. Use the timeless exception only when no current domain claim is present.

## Bundled-reference policy

Treat domain modules, exemplars, and templates as reusable structural guidance. Before using their version-sensitive details, check them against current sources. If a bundled reference conflicts with current authoritative information, prefer the current source, record the conflict, and update the reference only when the correction is durable and broadly reusable.

## Existing portfolio updates

When updating an existing large portfolio, prefer a source-ledger drift scan and stable-ID incremental impact analysis. Record checked-but-unchanged scopes, update only affected nodes and interfaces, preserve completed evidence, and create a revision diff. Rebuild the whole portfolio only when the north star, major role, horizon, regulatory context, or dependency architecture changes.

## Offline boundary

Offline operation may use a dated source archive or previous ledger for stable planning, but it cannot verify current web claims. Label volatile information as offline-unverified, aging, stale, inaccessible, or current-as-of the archive date. Queue online revalidation and do not treat cached material as current clinical, regulatory, safety, security, or authorization guidance.
