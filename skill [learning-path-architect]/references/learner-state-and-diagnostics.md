# Learner State and Diagnostics

Use this reference when current capability is uncertain, the learner wants to skip material, evidence conflicts, or a roadmap is stalled. Treat learner state as an evidence-backed working estimate, not a permanent label.

## State record

| Field | Meaning |
|---|---|
| Capability estimate | What the learner can currently do in the named context |
| Confidence | Low, medium, or high confidence in the estimate |
| Evidence source | Stated, observed, artifact, automated, mentor-confirmed, or unknown |
| Support level | Guided, familiar independent, bounded unfamiliar, or ambiguous/open-ended |
| Error pattern | The smallest recurring conceptual, procedural, transfer, environment, or evidence issue |
| Freshness | When the evidence was last checked and whether it may have decayed |
| Next diagnostic | The smallest task that can confirm, narrow, or falsify the estimate |

## Diagnostic proportionality

For a narrow request, use one or two skip checks. For a single roadmap, use a short branch diagnostic. For a large portfolio, diagnose only the branches that affect the first route and stage later diagnostics. Do not test everything before allowing useful progress.

A self-report can select a diagnostic but cannot by itself unlock an advanced branch. A demonstrated artifact may support skipping only the capability it actually exercises; it does not prove unrelated foundations.

## Diagnostic decisions

- **Skip if demonstrated:** evidence matches the objective, context, and independence required.
- **Sample first:** evidence is plausible but stale, narrow, or weakly verified.
- **Remediate:** a specific prerequisite or error pattern is exposed.
- **Start guided:** the learner cannot yet show the first prerequisite reliably.
- **Keep unknown:** evidence is insufficient; do not invent a level.

Record the smallest task and the decision reason. Preserve the state history when later evidence changes the estimate.
