# User Quick Start

Use this guide for the normal learner-facing workflow. Keep technical storage, schema, MCP, and adapter details out of ordinary replies unless the learner asks for them.

## What to say

- “Build my learning roadmap for [goal].”
- “Show me what I should do next.”
- “Update my progress: I completed [evidence].”
- “What is blocking the next step?”
- “Run a Discoverer review for fast-changing topics.”
- “Show what changed since the last revision.”
- “Undo the last update.”
- “Export my complete learning workspace.”
- “Tell me whether this workspace is permanently saved.”

## What the skill should do

First identify the smallest useful response mode. For a narrow question, answer narrowly. For a large or ongoing request, maintain a roadmap, progress record, current action, and review trigger. Expose one primary next action and, at most, one feasible parallel action.

At the start of a persistent-workspace request, state the current environment in plain language. For example: “This host can create an export, but it has not confirmed permanent storage.” Do not ask the learner to understand the underlying implementation.

## Normal hosted workflow

When the host is temporary, the learner should keep the exported workspace as the safe copy. A later session may require the learner to attach or reopen that workspace. If the host has verified project storage, use it, but still provide an export for backup before major changes.

## Normal local workflow

On the future local computer, keep the workspace in a backed-up folder, use Freeplane for visual maps, use the structured records for durable progress, and use Discoverer only through a verified scheduler or a manual review command.

## Guidance boundary

The skill guides what to learn, why it comes next, what evidence demonstrates progress, and when a route needs revision. It does not guarantee mastery, professional authorization, persistence, or current facts without evidence and environment verification.
