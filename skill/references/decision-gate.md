# Decision Gate

Use this gate before designing the route. Choose the smallest mode and resource set that can satisfy the request.

## 1. Identify the deliverable

| Signal in the request | Primary mode | Required behavior |
|---|---|---|
| “What should I learn?”, decomposition, prerequisites, skill tree | Standard map | Map outcomes, dependencies, and focused leaves; omit schedules. |
| “What first?”, “how should I study?”, sequencing, milestones, deadline | Roadmap | Add a starting point, ordered route, exit criteria, and advance-or-remediate loop. |
| Several distinct outcomes or a long wall of text | Portfolio roadmap | Ingest the whole request first; create goal families, shared foundations, route statuses, stable IDs, and a coverage ledger. |
| “Am I ready?”, level validation, readiness evidence | Assessment | Use branch-specific evidence and performance contexts; do not equate completion with mastery. |
| “Revise/update the previous map” | Revision | Preserve stable identifiers and completed work where practical; explain additions, removals, and dependency impacts. |

If two modes apply, use the more specific mode while retaining the standard map as the authoritative structure.

If the request includes any duration or ongoing study, activate the horizon mode: read `references/long-horizon-planning.md` and `references/capacity-and-replanning.md`, define the north star and phase/cycle/frontier layers, and model capacity without inventing precision. If the request asks for one giant syllabus, linked parts, local/cloud files, persistence, or progress tracking, activate the delivery mode: read `references/delivery-and-linking.md` and choose single document, linked parts, or workspace package.

## 2. Apply the three gates

1. **Scope gate:** Preserve explicit goals and constraints. Add an inferred prerequisite only when it closes a named capability gap; otherwise label it context-dependent, recommended, optional, or omit it.
2. **Freshness gate:** Use strict research for current, version-sensitive, regulatory, security, safety, compatibility, or user-requested claims. Use lighter verification for stable domain structure. Use the timeless exception only when the user explicitly removes current tools and domain claims.
3. **Risk gate:** For regulated, safety-critical, privacy-sensitive, or dual-use paths, separate learning evidence from authorization and prefer supervised, simulated, sandboxed, defensive, or reversible practice.
4. **Capacity gate:** Ask for or conservatively model available effort, variability, and desired parallel-branch limit. Use progress evidence when available. Never assume that parallel branches produce free speed.

## 3. Select references lazily

- Read `references/long-input-integration.md` and `references/active-frontier.md` only for large integrated paths.
- Read `references/multi-goal-prioritization.md` when priority is missing or competing priorities change the architecture.
- Read `references/proficiency-levels.md` for consequential level calibration; read `references/learning-science.md` only for retention, transfer, or long-horizon study behavior.
- Read `references/freshness-protocol.md` and the relevant research templates when the freshness gate activates.
- Read `references/risk-and-boundary-guide.md` only when the risk gate activates.
- Read `references/route-audit.md` for broad, constrained, multi-branch, or revised routes.
- Read `references/long-horizon-planning.md` for any explicit duration or ongoing program.
- Read `references/capacity-and-replanning.md` when availability, interruptions, cognitive load, maintenance, concurrency, observed throughput, sustainability, or periodic review affects the route.
- Read `references/delivery-and-linking.md` for single-document versus linked-part delivery, workspace detection, persistence, and progress integration.
- Read the smallest matching domain module after checking `references/domain-index.md`; otherwise state **Generic path — no bundled module**.

## 4. Keep the learner-facing output proportional

A narrow request should usually contain an outcome summary, learning map, and only material dependency notes. Add diagnostics, evidence tables, ledgers, freshness records, and route audits only when the request or gate requires them. Do not expose private graph construction or produce a resource dump in place of a route.
