# Diagnostic-first learning loop

Use this reference when the learner asks to skip material, reports difficulty, submits weak evidence, changes goals, misses a schedule, or asks whether a route should be expanded.

## Do not add content first

Before assigning more lessons, identify the smallest decision that needs to change. A learner may need a missing prerequisite, a clearer explanation, more practice, better feedback, a smaller task, more time, a transfer test, or a retention review. More content is only one possible intervention.

## Five-step loop

1. **State the target capability.** Describe what the learner should be able to do, not only what they should read.
2. **Inspect the available evidence.** Separate self-report, submitted work, reviewed work, tool checks, transfer, and retention. Mark missing evidence as unknown.
3. **Run a bounded diagnostic or pilot.** Choose the smallest task that distinguishes likely causes. A pilot should have a visible output and a stopping condition.
4. **Choose one intervention.** Select the smallest change that addresses the diagnosed cause. Keep other route changes proposed, not silently applied.
5. **Recheck the same signal.** Define what improvement would look like and when to reassess the route.

## Common diagnosis table

| Signal | Do not assume | Test or intervention |
|---|---|---|
| Learner cannot explain a concept | They need a whole new course | Ask for a short explanation or use a worked example |
| Learner can explain but cannot perform | They lack all theory | Assign a bounded practice task with feedback |
| Learner performs familiar examples but fails new ones | They have mastered the capability | Use a transfer task with changed conditions |
| Learner repeatedly makes the same error | They need more exposure | Record the error, identify its cause, and assign a corrective task |
| A project is late | The learner lacks discipline | Check scope, interruptions, setup friction, and estimate bias |
| Evidence is incomplete | The work is wrong | Mark the missing part unknown and request only the missing evidence |
| A route feels overwhelming | The learner needs more planning detail | Reduce the current action and defer the rest to the portfolio index |

## Pilot task rules

A pilot must be small enough to finish in one or a few sessions, representative of the intended work, and useful for estimating difficulty. Do not use a trivial task that cannot reveal the real bottleneck. Record expected time, actual time, evidence quality, and the route decision it informs.

## Recovery after a miss

When a learner misses a task or schedule, preserve completed work and ask what changed only if that answer affects the route. Choose one response: resume, reduce scope, split the task, move the deadline, change the session size, or pause deliberately. Do not automatically backfill every missed session.

## Route-change record

Whenever the route changes, preserve:

- The original assumption.
- The evidence or event that challenged it.
- The decision taken.
- What remains unchanged.
- The next calibration or review trigger.

A route revision is not proof that the earlier plan was foolish; it is evidence that the plan was updated using new information.
