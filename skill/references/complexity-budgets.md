# Complexity Budgets

Use complexity budgets to keep a huge portfolio usable. Budgets are adjustable defaults, not hard universal limits.

Track active domains, active branches, current actions shown, mandatory resources, unresolved decisions, integration studios, tracker burden, research scope, and learner-facing text. When a budget is exceeded, compress, group, stage, defer, or move detail behind an index rather than expanding the immediate response.

The learner may request a giant syllabus, but still provide an index, stable IDs, search/navigation anchors, current frontier, and staged details. A narrow query should return only the relevant slice. Do not load or expose every resource merely because the portfolio contains it.

Explain when a budget changes the output: for example, “I preserved all 120 domains in the index but expanded only the four active families.” Complexity control protects actionability; it does not delete user goals.
