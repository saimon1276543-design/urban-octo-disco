# Learner Intake Contract

Use this reference when the learner asks for a roadmap, portfolio, schedule, or adaptive plan and the destination is not fully specified. Gather only information that can change the route.

## Minimum useful fields

| Field | Why it matters | If missing |
|---|---|---|
| Desired outcome and real-world context | Defines the capability and evidence context | Infer only from explicit wording; otherwise ask one focused question |
| Current level by family | Prevents repeating demonstrated foundations | Use a short diagnostic or mark entry uncertainty |
| Target level/evidence standard | Controls depth and independence | Infer the lowest level consistent with the outcome and state it |
| Reliable availability | Converts effort into sustainable calendar planning | Use a conservative band, not nominal hours |
| Horizon/deadline | Controls minimum viable route and scope trade-offs | Use an evidence-defined open horizon |
| Parallel-branch preference | Controls concurrency and switching load | Start with one primary branch and at most one low-conflict parallel branch |
| Existing work/resources/progress | Prevents duplicate learning and supports calibration | Mark unknown; do not assume completion |
| Delivery preference | Chooses single syllabus, linked parts, workspace, or inline output | Use the smallest response mode |

## Intake rule

Ask only one question when its answer would materially change the architecture, safety boundary, or feasibility. Otherwise make a conservative assumption and expose it in the assumption ledger. Never demand a full questionnaire before producing a useful first step.

## Intake output

For a consequential plan, summarize the interpreted destination, current gap, target evidence, constraints, assumptions, and unresolved choice. Let the learner correct the interpretation before a large route is finalized when the uncertainty is material.

## Common clarification questions

Use one of these only when necessary:

- “What real-world outcome should this learning enable?”
- “Which of these goals is primary if they compete for time?”
- “What can you already do independently without a tutorial?”
- “How much reliable time can you protect, after interruptions and recovery?”
- “Do you want one giant syllabus, linked parts, or only the current next steps?”
- “What evidence would convince you that this capability is usable?”

Do not ask a question whose answer would not change the route.
