# Shortest Credible Route Audit

Use this audit for broad, constrained, multi-branch, or revised paths. It is a decision aid, not a mathematical proof that one curriculum is globally optimal.

## Audit definition

A shortest credible route must satisfy all five conditions:

1. **Outcome coverage:** every explicit target capability or deliverable maps to at least one node and appropriate evidence.
2. **Prerequisite justification:** every required inferred branch has a target capability, rationale, and activation condition where context matters.
3. **Evidence sufficiency:** the route reaches the requested proficiency through branch-appropriate performance evidence, not topic completion alone.
4. **Non-linearity honesty:** alternatives, parallel branches, reinforcement loops, and operational prerequisites are represented without forcing a single sequence.
5. **Minimality:** removing any required branch would omit an outcome, create a dependency gap, or invalidate the evidence claim. Otherwise downgrade it to Recommended, Optional, Alternative, or Omit.

## Route trade-offs

Record only consequential trade-offs. For example, a project-first route may reach one practical outcome sooner while leaving breadth gaps; a breadth-first route may improve orientation while delaying independent performance. State which capability is gained, deferred, or unavailable under the selected route.

## Anti-bloat checks

Do not keep a branch merely because it is traditional, adjacent, popular, or present in a bundled domain module. Do not add a second project when one artifact already supplies sufficient evidence. Do not split a leaf when the split would not change the learner’s action, prerequisite, evidence, or decision. Do not claim minimality when the user’s goal, context, or target proficiency is still materially ambiguous; mark the audit provisional instead.

## Revision rule

When revising an existing map, compare the old and new audit tables. A new required branch must identify the newly exposed outcome, dependency, evidence gap, or changed context that justifies it. A removed or downgraded branch must state what remains covered and what, if anything, is no longer available.
