# Durable Knowledge Policy

Use this reference when the learner asks for timeless, base, foundational, or long-term knowledge.

## Layer claims by volatility

| Layer | Examples | Handling |
|---|---|---|
| Durable | Mathematics, algorithms, protocols as concepts, dependency relations, scientific reasoning, safety principles | Teach directly and preserve as stable curriculum nodes |
| Medium-term | Design patterns, common architectures, engineering practices, mature tool families | Teach with context and periodically review |
| Volatile | Framework APIs, model releases, browser behavior, cloud products, exam notices, regulations, vendor syntax | Attach source, date, version/region, and revalidation trigger |
| Current verification | Official syllabus, eligibility, live service capability, active policy, current package support | Research before asserting; queue revalidation |

Never describe a generated curriculum as an official syllabus, certification, medical qualification, rank guarantee, production-readiness proof, or current compatibility guarantee. Preserve the learner's wording in the coverage ledger, but normalize tools into the durable capability they support.

## Durable-module contract

Every domain module should state its stable outcomes, prerequisites, canonical learning units, evidence artifact, common misconceptions, safety boundary, volatile overlays, and cross-domain bridges. Keep implementation syntax and vendor details out of the durable core unless they are explicitly marked as versioned examples.

## Current-source split

When a request mixes foundational and current material, produce two linked layers: a durable foundation and a dated current-verification overlay. State what was researched, what was not researched, the cutoff, affected nodes, and the next recheck trigger.

## Quality rules

Prefer principles over product lists, causal explanations over memorized commands, and transferable evidence over topic exposure. Do not use a single project to claim mastery of every connected domain. For medical, investigative, security, model-modification, and browser/crawling topics, preserve authorization, privacy, safety, and professional boundaries.
