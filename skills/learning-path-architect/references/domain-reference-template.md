# Domain Reference Template

Use this file as a pattern when a recurring domain needs specialized decomposition guidance. Create one focused reference per domain rather than adding domain trivia to the core skill.

## Domain

State the domain and the kinds of learning requests it covers.

## Canonical prerequisite families

List only high-confidence prerequisite families that commonly gate this domain. For each family, state the capability it unlocks and conditions under which it can be skipped.

## Common branch structure

Describe a useful ordering of foundations, theory, implementation, tools, systems, practice, and applications for this domain. Keep named technologies and alternatives explicit.

## Domain-specific leaf patterns

Provide concise examples of good focused learning units. Use domain-appropriate verbs such as derive, implement, configure, interpret, debug, evaluate, or produce.

## Frequent misconceptions and boundary conditions

List only misconceptions that materially derail learners in this domain. Pair each with a corrective learning unit or milestone.

## Proficiency calibration

For each relevant level—Novice, Advanced Beginner, Competent, Proficient, and Expert—state what independence, ambiguity, transfer, judgment, and scope look like in this domain. Do not define levels by topic count.

## Typical milestone evidence

Describe observable demonstrations that indicate readiness for the next phase. State the performance context and permitted support. Prefer transfer tasks over recall questions.

## Current or version-sensitive details

Record which claims must be checked against current primary or authoritative sources. Do not treat this section as a substitute for fresh verification.

## Scope guardrails

State what should not be added automatically, which topics are optional, and which popular tools or credentials are alternatives rather than universal requirements.
